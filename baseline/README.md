# baseline/

Before-agents baselines for the `netsuite_ingestion` pipeline, on synthetic data:

* **v1** (`before_agents_report.md`): the original per-date bronze design, run in prod.
* **v2** (`before_agents_report_v2.md`, `v2/`): the redesigned pipeline (single streaming bronze
  table, once-flows, key ledger with fingerprints, full-refresh guard), run in the dev target.

All data here is generated by `tools/netsuite_gen.py` (fake names, synthetic keys); nothing comes from a
real system. What is committed and what is not follows two rules:

1. **No raw row dumps.** The full metric snapshots contain `row_state`, the business key and dates of every
   silver and rejected row (about 30,000 entries per table). Those full files live in `baseline/raw/`
   (git-ignored). The committed snapshots are the same files with `row_state` removed
   (`python baseline/strip_row_state.py`); the report builders do not read `row_state`, and the reports
   rebuild byte-for-byte from them.
2. **No environment identifiers.** Files carrying the workspace host, an email, run-page URLs or object ids
   are git-ignored. (The reports and `v2/guard_negative_test.txt` still mention a few pipeline, job and
   update ids as evidence; those are object ids, not hosts or credentials.)

## Files

| File | Contents | Committed |
|---|---|---|
| `before_agents_report.md` | v1 report: runs A (clean), B (defects, full refresh), C (increment, normal run: failed), defect classification, reconciliation, 9 findings | yes |
| `before_agents_report_v2.md` | v2 report: steps B, C and D on the redesigned pipeline, comparison with v1, guard and canary results | yes |
| `once_flow_experiments.md` | Results of the `append_flow(once=True)`, planning-cost and full-refresh-detection experiments | yes |
| `build_report.py`, `build_report_v2.py` | Generate the two reports from the snapshots, manifests and classifications | yes |
| `collect_metrics.py` | Collects a snapshot after a run (counts, rejects, run_audit, pipeline/job state, row_state) | yes |
| `classify_defects.py` | Classifies every injected defect row (rejected, passed, absorbed, failure); needs `row_state` (raw snapshot) | yes |
| `strip_row_state.py` | Writes the committable snapshots from `raw/` | yes |
| `defects_baseline.yaml`, `increment_config.yaml` | Defect rates used for the baseline `--init` and `--increment` runs | yes |
| `clean.json`, `defects_full.json`, `incremental.json` | v1 metric snapshots for runs A, B, C (no `row_state`) | yes |
| `v2/B.json`, `v2/C.json`, `v2/D.json` | v2 metric snapshots for steps B, C, D (no `row_state`) | yes |
| `manifest_clean.json`, `manifest_defects.json`, `manifest_increment.json`, `v2/manifest_B/C/D.json` | Ground truth: exactly which synthetic rows carry which injected defect (business keys, counts, late-row dates), plus backup names | yes |
| `classification_full.json`, `classification_incremental.json`, `v2/classification_B/C/D.json` | Outcome of every defect row per defect and per table (aggregates) | yes |
| `v2/canary_result.json` | Result of the final guard-canary run | yes |
| `v2/guard_negative_test.txt` | The guard's BLOCKED message from a real blocked full refresh, with the row counts before and after | yes |
| `raw/**` | Full snapshots including `row_state` (raw row dumps, about 5 MB each) | **no** (ignored) |
| `run_*_job.json`, `run_*_job.err` | Raw Jobs API responses (workspace host, user email, run-page URLs) | **no** (ignored) |
| `v2/*.log` | Console logs of job runs (workspace host, user email) | **no** (ignored) |
| `v2/dev_resources.txt` | Dev pipeline and job object ids (regenerate with `databricks bundle summary -t dev`) | **no** (ignored) |

## Regenerating

```bash
python baseline/collect_metrics.py --label v2_B --job-run-id <id> --out baseline/raw/v2/B.json --layout v2 \
    --catalog workspace --pipeline-id <dev pipeline id> --warehouse-id <SQL warehouse id>
python baseline/classify_defects.py baseline/v2/manifest_B.json baseline/raw/v2/B.json baseline/v2/classification_B.json
python baseline/strip_row_state.py
python baseline/build_report_v2.py
```
